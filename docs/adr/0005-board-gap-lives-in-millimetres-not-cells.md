# 5: 板缝只进物理尺寸，豆格坐标里板是紧挨着的

`BoardLayout.gapMm`（板与板之间的实测缝隙）**不占用豆格坐标**：一块板的最后一列和下一块板的第一列在 `(col, row)` 里是相邻的。缝只体现在物理长度上——每跨过一条板缝，毫米数就多一个 `gapMm`。

同理，`BoardRect` 上不再有 `row`/`col`，只有 `index`（用户可见的板序号）。自由摆放时"第几行第几列"是无意义的坐标：L 形、阶梯形里的板根本不在行列网格上。

理由：豆格坐标必须能直接映射到"第几块板的第几个钉"，这是编辑、跟做、去重和一切按色统计的基础。如果缝占格子，就得往画布里塞一批"缝格"，所有逐格循环都要先判断"这格是不是缝"——而这件事已经有更好的答案（`placeable` 空档遮罩）。物理长度是另一回事，它只需要在算毫米的地方加上缝。

"板号是序号"是同一件事的另一面：打印件上写 `Board 3`，用户在台面上按摆放顺序数到第 3 块就对上了；写 `r1c5` 反而要求用户理解一个数据模型里根本不存在的坐标系。

## Considered Options

- **让缝占整数格**（把 gapMm 向上取整成 1-2 格宽的空白列）：坐标里能看出缝，但凭空多出不可编辑的格子，且按板导出/按色统计都要额外特判。
- **只存毫米、豆格坐标忽略缝**，物理尺寸独立计算 ← 选定。
- **不支持 gapMm**（直接删掉）：最省事，但板上真实存在的缝会在 1:1 打印时逐板累积成可见错位。

## Consequences

- `layoutSizeMm()` 的宽度 = 豆格数 × 针距 + 跨过的板缝条数 × gapMm。板数越多，缝的累计越明显，所以它不能省。
- 多带混排（一条 104 带 + 一条 52 带）时两条带的缝条数不同，物理宽度取较大的那个值——是个上界，但比忽略缝更接近实物。
- 导出文件名与页眉里的板号只能写 `板 1/2/3` 和 `Board 1/2/3`；任何"行列号"都必须由摆放位置推导，不能再拿数组下标冒充。
- `gapMm` 目前没有界面入口（实测为 0）。加入口时只影响物理尺寸与缝宽标注，不动豆格坐标——这条边界就是本 ADR 的全部价值。
